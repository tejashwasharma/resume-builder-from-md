## Before you drill these

Search for `FILL IN` and answer every one:

```bash
grep -rn "FILL IN" .
```

Those markers are the details only you have — what the 13 seconds was actually
doing, how big the RBAC team was, why you left. I've deliberately left them
blank rather than inventing something plausible: **a story that collapses on
the second follow-up is worse than one you never told.**

## How to use these

1. Read a story. Fill in its gaps.
2. Say it out loud, timed. Two minutes for the STAR, then stop.
3. Run `/mock-interview behavioral` — it asks these and pushes on the
   follow-ups without warning you which.
4. Anything you fumbled goes in `progress/log.md` automatically.

## The one rule

Interviewers don't test whether the story is impressive. They test whether
it's **yours**. Specificity is the only thing that proves that: the actual
bottleneck, the actual argument you lost, the number you had to revise. Vague
achievement language reads as borrowed no matter how true it is.
